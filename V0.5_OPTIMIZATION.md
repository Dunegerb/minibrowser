# MiniBrowser V0.5 — optimization pass

## Why V0.4 grew on disk

V0.4 persisted the entire Chromium profile cache and wrote every network request twice: once to Network Audit and again through the Machine Flight Recorder. The audit files were daily/unbounded.

## V0.5 changes

- CefSharp.Wpf.HwndHost native HWND rendering instead of WPF off-screen bitmap rendering.
- PerMonitorV2 DPI manifest.
- GPU compositing restored for HwndHost.
- Chromium HTTP cache target: 64 MiB.
- Volatile HTTP/image cache, code/GPU/media cache, Service Worker CacheStorage/blob cache and Chromium History are removed before startup.
- Cookies, localStorage, IndexedDB and Service Worker registrations remain persistent, using the same V0.4 profile path.
- Session history implemented in memory, max 300 entries.
- Network Audit is now a 3 x 8 MiB rotating ring (about 24 MiB max on disk).
- Flight Recorder no longer duplicates raw network request events; compact semantic events remain, legacy oversized files are trimmed, and preserved snapshots are gzip-compressed and capped to 20 files / 128 MiB total.
- While the stub Machine bridge is active, resource requests are audited locally without allocating high-volume Machine protocol envelopes; that stream turns on automatically for the Named Pipe bridge.
- Manual “Limpar cache” uses IRequestContext.ClearHttpCache and leaves cookies/site data intact.
- Google is no longer hard-coded as the omnibox search provider. DuckDuckGo is the default.
- GitHub Actions generates Portable and Thin builds and prunes unused locale packs/XML/PDB files.

## Package size reality

CEF/Chromium itself is the dominant part of the package. The Thin build removes the bundled .NET Desktop Runtime but requires .NET 8 Desktop Runtime on Windows. The Portable build works without a local .NET installation. Both retain the same Chromium engine/security functionality.
